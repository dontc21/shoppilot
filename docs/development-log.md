# ShopPilotBot 开发日志

本文只记录实际发生且能够说明证据来源的开发过程。由于项目在建立 Git 仓库前已经进行过若干实验，首次提交之前的内容属于“基线前开发记录”，不是由 Git commit 时间线恢复出的历史。

## 2026-10-14：最初尝试接入拼多多商家客服

### 问题表现

项目最初计划通过 Playwright 控制独立 Edge，在店主手动登录后读取拼多多商家客服网页。一次性 DOM 检测结束后，Playwright 控制的 Edge 窗口随程序退出而关闭，不符合持续监听要求。

### 排查方法

- 检查浏览器上下文的创建与清理位置。
- 区分平台主动关闭、进程被终止和 Python 正常退出 Playwright 上下文。
- 将浏览器生命周期调整为持续循环，只在 `Ctrl+C` 或异常退出时清理 context。

### 观察证据

- 窗口关闭发生在检测脚本结束之后。
- 后续长驻模式能够让浏览器在检测完成后继续保持打开。
- 当前仓库未保留当时的拼多多平台代码或原始日志，因此不能从 Git 历史复原更细粒度证据。

### 处理结果

确立了“持久化用户目录 + 手动登录 + 长驻监听 + 退出时清理”的浏览器生命周期设计。

### 当前状态

拼多多接入已停止。相关配置和运行目录未进入当前项目基线；该阶段不构成已完成的平台接入。

## 2026-10-14：切换到 B站小店

### 问题表现

项目目标从拼多多商家客服切换为 B站小店。两个平台的登录状态、页面结构和定位器不能混用。

### 排查方法

- 将平台页面操作集中到 `BilibiliShopAdapter`。
- 使用独立的 `edge_bilibili_profile/`。
- 保留平台无关的消息模型、SQLite 去重和浏览器生命周期代码。
- 删除当前项目中的拼多多平台配置，但不删除任何真实浏览器登录目录来“解决”问题。

### 观察证据

- B站商家首页能够在 Playwright 控制的 Edge 中正常打开。
- 店主能够手动完成登录并看到商家后台。

### 处理结果

当前代码只包含 B站小店适配器，发送接口在阶段一固定抛出 `DRY_RUN` 安全错误。

### 当前状态

B站商家后台登录和持久化配置已真实验证；消息 DOM 尚未完成真实验收。

## 2026-10-14：客服入口曾停留在 `about:blank`

### 问题表现

店主点击商家后台顶部“客服系统”后，曾出现一个标题为“无标题”、地址停留在 `about:blank` 的新标签页。

### 排查方法

在店主再次手动点击前安装以下只读监听：

- BrowserContext `page`、`requestfailed`、`response`。
- Page `popup`、`framenavigated`、`console`、`pageerror`。
- 客服入口捕获阶段只记录标签、静态类名和链接行为。
- 网络日志只保留脱敏域名、路径、资源类型、状态码和错误类型。

### 观察证据

再次测试时：

- “客服系统”实际元素为由 JavaScript 事件代理处理的 `span`，不是普通链接。
- 捕获到一个 popup 和一个新页面。
- 客服主文档请求返回 HTTP 200。
- popup 主 frame 成功导航到客服页面。
- 点击后没有 console error、pageerror、requestfailed 或 HTTP 4xx/5xx。
- 页面加载过程中出现过子 frame 的临时 `about:blank`，但主页面最终成功加载。

### 处理结果

新增脱敏诊断工具，并让诊断完成后的 Edge 保持打开直到店主按 `Ctrl+C`。

### 当前状态

原始故障没有再次复现，根因尚未确定。不能将其描述为已解决的 Playwright 兼容性问题。若再次发生，应保留当次监听证据，不自动重复点击或猜测内部客服地址。

## 2026-10-14：准备当前会话消息读取与去重

### 问题表现

需要从真实客服页识别当前买家会话、买家消息、商家消息和稳定消息 ID，同时不得遍历其他真实买家或保存完整聊天记录。

### 排查方法

- 从 `context.pages` 查找已验证的客服主文档，而不是假设首页就是客服页。
- 增加 `probe-chat`，只围绕店主明确发送的“你好”采集脱敏 DOM 路径。
- 将读取范围限制为店主当前打开的一个会话，不自动点击会话列表。
- 优先使用平台消息 ID；缺失时使用多字段 SHA-256 回退指纹。
- SQLite 只保存消息哈希、脱敏会话键和首次观察时间。

### 观察证据

- 代码和自动化测试已经完成。
- 2026-10-14 运行 Pytest，结果为 `13 passed`。
- 真实客服消息选择器尚未从测试消息 DOM 中确认。

### 处理结果

已准备好在不重复重启 Edge 的情况下完成“结构探测 → 填写真实定位器 → 当前会话监听”的流程。

### 当前状态

尚未完成真实平台验收。后续必须依次验证：

1. 当前会话消息列表定位。
2. 买家消息与商家消息区分。
3. 第一条新消息只输出一次。
4. 第二条消息能够被识别为新消息。
5. 程序重启后历史消息不会再次处理。
